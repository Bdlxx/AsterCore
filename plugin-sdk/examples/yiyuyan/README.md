# 易语言原生插件开发指南（栖星 AsterCore）

> 适用：《ABI草案.md》v0.2（nap_plugin.h）· 平台仅 Windows x64
> 易语言可产出 DLL，但有三条历史包袱必须先处理，否则用户机器跑不起来。

## 一、硬性要求

1. **x64 编译**：AsterCore 主程序为 x64（Python 3.12 x64）。易语言默认 x86，需使用支持 64 位的编译环境（如 黑月/火山/官方 x64 支持库）。
2. **cdecl 调用约定**：插件导出的 `nap_plugin_*` 必须是 **cdecl**（C 默认约定）。易语言"公开子程序"默认是 stdcall 风格，**必须**在支持库/声明层改为 cdecl，否则主程序调用时栈错位、直接崩溃。
3. **运行库随包分发**：易语言 DLL 依赖 `krnln.fnr`、`spec.fne` 等支持库。发布插件包时**必须把所需支持库放进同目录**（或提示用户安装），否则加载失败。

## 二、字符串传递（最重要）

ABI 约定所有入参/出参为 `char*`（UTF-8，无 BOM）。易语言文本是**宽字符 + 自身内存格式**，不能直接当 `char*` 用：

```
主程序 → nap_plugin_on_event(char* event_json)      ← 收到的是内存指针（GBK/UTF-8 字节）
插件内部：先按字节拷贝到字节集，再转易语言文本后解析 JSON
返回：nap_plugin_* 导出函数都返回 int（没有字符串返回值，规避释放问题）
```

**推荐做法**：导出函数内部只用整数与字节集打交道；JSON 解析用现成的易语言 JSON 模块；
调用主程序动作（发消息）时，构造 JSON 文本 → 转字节集 → 调 `api.action`（回调函数指针）。

## 三、与 C 模板对照（nap_hello.c 语义翻译）

| C 步骤 | 易语言做法 |
|---|---|
| `nap_plugin_init(config, api)` | 公开子程序，参数 `config` 为整数(指针)；把 `api` 指针保存到全局变量（后续调 action/log 用） |
| 检测 `"type":"message"` | 字节集查找（注意事件 JSON 是**紧凑无空格**格式） |
| 提取 `"raw":"..."` | 字节集找 `"raw":` 后取到下一引号前（**跳过 7 字节**：`"raw":` + 开引号） |
| 命中回复 | 拼动作 JSON → 调保存的 api.action 回调（`api` 结构体第一个字段是版本号，后面是指针——用易语言的"取结构体成员"或按字节偏移调用，建议用支持结构体的编译器封装） |

## 四、最小插件骨架（伪码）

```
.版本 2
.程序集 nap_hello, , , "nap_hello.dll"

.全局变量 g_api, 整数型   ' NapApi* 保存

.子程序 nap_plugin_abi_version, 整数型, 公开
    返回 (1)

.子程序 nap_plugin_name, 整数型, 公开   ' 返回 char*（静态 UTF-8 字节集指针）
    返回 (取变量数据地址 (静态名))

.子程序 nap_plugin_init, 整数型, 公开
    .参数 config_json, 整数型
    .参数 api, 整数型
    g_api = api
    返回 (0)

.子程序 nap_plugin_on_event, 整数型, 公开
    .参数 event_json, 整数型
    ' 读字节 → 找 "type":"message" 与 "raw": → 命中回调用 g_api 内 action
    返回 (0)  ' 未处理

.子程序 nap_plugin_unload, 公开
```

> ⚠️ 以上为结构示意，实际编写需在你的易语言环境验证 cdecl 导出与结构体指针调用；
> 建议先完整跑通 C 模板，再把 C 逻辑平移，避免两头踩坑。

## 五、发布清单

```
插件包/
├─ 你的插件.dll
├─ krnln.fnr / 相关支持库（随包）
└─ 说明.txt（要求：AsterCore x64、Python 3.12 运行库、cdecl 说明）
```
放置：插件目录 `data/<账号>/plugins/<名>.dll` 即被统一加载器识别（原生 C-ABI 通道 + 子进程隔离）。

## 六、优先级建议

易语言模板放**语言模板最后批次**：C / Rust / C++ 已验证可产出合规 DLL；
易语言主要卡在 cdecl/x64/支持库三条，建议社区有人需要时再补完整示例工程。
