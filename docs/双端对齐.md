# 双端对齐（Linux ↔ Windows）

> 前提（用户明确）：**Windows 版是现有 Linux 版的移植/改造，不是另起炉灶。**
> 计划书依据：§4「与现 Linux 多实例架构（instances/<QQ>）逻辑一致」·
> §5.2「保持现有 SDK 接口不变」· §10「data 结构保持兼容，文档说明迁移步骤」。
>
> 现状：**Linux 版 5 个线上插件已可在 AsterCore 里零改动运行**（详见 §3 验证）。

---

## 1. 结论先说：对齐的关键不是"重写功能"，而是"让老插件照旧跑"

Linux 版插件契约（`/root/mybot2/main.py` 与各插件）：

```python
# 同步、收 OneBot v11 原始 dict、返回 bool
def handle(event: dict) -> bool: ...

from utils.api import send_message, send_post_forward_msg, http_get
from utils.config import get_config, get_master_qq, get_qq, ...
from utils.plugin_toggle import is_enabled, set_enabled
from utils.command_registry import CommandRegistry
```

AsterCore 原本是自研 SDK（async + `Event`/`Segment` 模型 + `PluginMeta`），
**老插件一个都跑不起来**。因此新增兼容层 `src/astercore/compat/`，把两者缝上：

| 文件 | 作用 |
|---|---|
| `onebot.py` | `Event` ↔ OneBot v11 原始 dict；CQ 码 ↔ 消息段（双向） |
| `context.py` | 账号上下文：事件 `self_id` → contextvar → 唯一账号，三级兜底 |
| `utils_pkg.py` | 向 `sys.modules` 注入 `utils` 包（api/config/log/ws/plugin_toggle/command_registry） |
| `legacy.py` | 老插件识别（同步 `handle` + 无 `__meta__`）与适配：丢线程池执行、复制上下文 |
| `paths.py` | 出口路径映射（老插件硬编码的 `/app/cache/images` → 本机 NapCat 目录） |

内核侧的配合改动：

- `bus.py`：**多目录加载**（共享新 SDK 目录 + 账号实例目录）；老插件记为 `kind=legacy`；
  模块命名空间按账号隔离（同名插件多账号互不干扰）；**无 `handle` 的文件跳过**
  （与 Linux 版一致：`parser_bridge.py`/`jm_worker.py` 不是插件）；
  注入 `plugins` 命名空间包，支持老插件之间的 `from plugins.xxx import yyy`
- `runtime.py`：账号实例目录、显示名、事件循环；分发时设置账号上下文
- `onebot.py`(backend)：**保留 NapCat 原始报文**（`extra._onebot`），老插件零损耗还原
- `onebot_mapping.py`：补 `send_group_forward` / `send_private_forward`

## 2. 目录布局对齐（按计划书 §4）

```
Linux（现状）                          Windows（AsterCore）
instances/<QQ>/                        accounts/<QQ>/
├─ plugins/*.py      ← 老插件          ├─ plugins/*.py       ← 同一份，原样拷过来
├─ data/*.json       ← 插件数据        ├─ data/*.json        ← 同一份，原样拷过来
├─ config.json       ← BOT_NAME/…      ├─ config.json        ← 同一份（兼容层读取）
└─ venv/                               ├─ venv/ (可选，JM 子进程用)
                                       └─ backend.json       ← 新增：AsterCore 连接配置
```

- 老插件用 `os.path.dirname(__file__)/../data` 定位数据 → 在 AsterCore 下自然落到
  `accounts/<QQ>/data/`，**与 Linux 完全一致**，数据可直接拷贝。
- `utils.plugin_toggle` 的 `plugin_toggle.json` 同样落在账号 `data/` 下。
- **分群开关键名必须与线上一致**（不是文件名）：`wordlib` / `marry` / `pseudo` /
  `jm_downloader` / `video_parser`。写成 `pseudo_persona` 会让伪人插件的分群开关静默失效。

## 3. 已验证的事实（实测，非推断）

加载：把线上实例的 `plugins/` 与 `data/` 整体搬进 `accounts/<QQ>/` 后

| 插件 | 加载 | 说明 |
|---|---|---|
| wordlib | ✅ | kind=legacy，线上 41KB 版本，一行未改 |
| marry | ✅ | |
| pseudo_persona | ✅ | 显示名按开关键 `pseudo` 反查为"伪人插件" |
| video_parser | ✅ | 内部 `from plugins.parser_bridge import …` 已支持 |
| jm_downloader | ✅ | |
| parser_bridge / jm_worker | 跳过 | 与 Linux 版一致（无 `handle`） |

功能（用线上真实数据与真实分群开关）：

- `签到` → 真实签到：`sign_data.json` 从 `{last_date}` 变为 `{total:1, last_date:今天}`，
  并回复到正确群
- `签到排行` → 读取线上签到数据正常出榜
- `转码` → 词库插件的转码指令正常回复
- 未开启词库的群发 `签到` → 事件链 `passed`（分群开关生效）
- 无意义文本 → `passed`（不误吞）

## 4. 剩余待办（按"不做一定坏"排序）

来自插件逐行盘点（`P0` 必须做，`P1` 行为对齐，`P2` 顺手修）：

### P0 · 不做会在 Windows 上坏
| # | 问题 | 方案 | 状态 |
|---|---|---|---|
| 1 | 插件硬编码 `/app/cache/images`（容器路径） | 兼容层出口映射到本机目录；Windows 默认 `%USERPROFILE%\napcat\cache\images`，可用 `NAPCAT_CACHE_PREFIX/HOST` 覆盖；Linux/Docker 默认不映射（保持线上行为） | ✅ 已实现 |
| 2 | JM 子进程 stdout 编码（Windows 默认 cp936 → 中文进度行丢失） | 启动时设 `PYTHONIOENCODING=utf-8` / `PYTHONUTF8=1`，子进程继承 | ✅ 已实现 |
| 3 | 老插件写文件目录 `~/napcat/cache/images` | 启动时自动创建 | ✅ 已实现 |
| 4 | JM 找解释器用 `venv/bin/python`（Windows 是 `venv\Scripts\python.exe`） | Windows 下自动在 `venv/bin/` 放两个名字的副本（`python` 供插件探测、`python.exe` 供 CreateProcess），并**覆盖**从 Linux 拷来的 ELF 副本；插件侧探测顺序补 `Scripts/python.exe`，冻结版拒绝拿主程序自身当解释器 | ✅ 已实现 |
| 5 | `ZoneInfo("Asia/Shanghai")`（wordlib/marry）Windows 无 tzdata | 依赖加 `tzdata`，PyInstaller 收集其数据 | ✅ 已实现 |
| 6 | 视频解析核心需要 `ffmpeg` 在 PATH | 兼容层启动时定位并把所在目录插到 PATH 最前面（`FFMPEG_PATH` → `<安装目录>/tools/ffmpeg/bin` → 系统 PATH），找不到只告警不阻塞 | ✅ 已实现 |
| 7 | 解析核心 `cookie_dir` 用 5 层 `dirname` 推算仓库根 | 优先用 `ASTERCORE_HOME`（兼容层启动时固化）兜底；未设置时行为不变 | ✅ 已实现 |
| 8 | 解析核心依赖较重（aiohttp/yt_dlp/bilibili-api/curl_cffi/msgspec/PIL/json5/bs4/httpx） | **已实测**：36 个包全部有 Windows 轮子（`curl_cffi` 还是 abi3），零编译；仅 `qrcode-terminal` 需允许 sdist；体积约 21 MB | ✅ 已定论（见专题） |
| 9 | 三个插件把 NapCat 缓存目录写死成 `/root/napcat{,2}/cache/images` | Windows 上 `/root/…` 会被当成本盘根目录，`makedirs`/写文件**都会成功**但落到 `C:\root\…`，而发送路径被映射到 `%USERPROFILE%\napcat\cache\images\…` → 解析成功却发不出去。修法：显式配置 → 非 Windows 才用老路径 → `~/napcat/cache/images`；jm 另需"写入目录=发送路径"（它的 PDF 走 HTTP 直发，绕过出口映射） | ✅ 已实现 |
| 10 | 中文 Windows 上插件 `print("⚠ …")` 抛 `UnicodeEncodeError`（U+26A0 不在 GBK） | 兼容层启动时 `force_utf8_stdio()`：本进程 stdout/stderr reconfigure 成 UTF-8 + `errors="replace"`（设 `PYTHONUTF8` 只影响子进程，改不了当前进程） | ✅ 已实现 |

> 依赖链专题（含打包配方、逐文件审计结论与 backlog）：[Windows-视频解析依赖链.md](Windows-视频解析依赖链.md)


### P1 · 行为对齐
- 热重载：Linux 用 `SIGUSR1`（Windows 无信号）→ 改为面板触发 / 文件监听自动 reload
- 导入期快照：`MASTER_QQ`/`BOT_QQ`/`NAPCAT_HTTP`/`ACCESS_TOKEN` 在插件导入时读一次；
  改配置需重启（面板"重载插件"可覆盖），保持与 Linux 一致即可
- `MASTER_QQ` 比较：wordlib 用整数比较、其他插件用 `str()` —— 迁移时保持原样，别"顺手统一"
- 插件加载顺序有意义（字母序）：`pseudo_persona` 排在 `video_parser` 之前，
  并在代码里硬编码放行 `B站登录/开启视频解析/关闭视频解析`。**别改成无序分发**
- `jm_downloader` 的 token 严格校验（`^\d{3,10}$` / `^p\d{3,10}$`）是刻意的"不误吞"，别简化

### P2 · 顺手清理（可选）
- 不打包死代码：`video_parser_core/clean.py`（引用不存在的配置键）、`render.py`（空壳）
- 无消费者的配置键照原样保留（面板显示但不影响行为），避免"看着像没实现"的误解

## 5. 面板/服务层待对齐

Linux 版 Flask 面板（`web/api.py`：双 bot 启停、日志尾巴、插件配置表单、二维码登录）
与 AsterCore 面板（账号/插件/日志/调试台/鉴权）功能面不同。对齐方向：
**面板按账号维度组织**（`accounts/<QQ>/` 一个账号一张卡），把老插件的
`*_config.json` 表单化，并提供 `plugin_toggle.json` 的分群开关矩阵。

---

## 6. 明确不做的事（避免"另起炉灶"）

- 不重写插件、不改 `utils.*` 语义、不迁移数据格式
- 不把 `Event`/`Segment` 新模型强加给老插件（新 SDK 与兼容层**并存**，各自可用）
- 不依赖文件名排序之外的新分发机制（保持字母序语义）
