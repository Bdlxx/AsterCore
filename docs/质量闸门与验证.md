# 质量闸门与验证（当前状态）

> 目的：把"现在有哪些自动化保障、各能挡住什么、还缺什么"写清楚 —— 避免出现
> "以为有闸门、其实没有"的情况（本项目真实发生过：CI 从装完依赖直接打包，**从不跑测试**）。
> 更新日期：2026-10-14（v0.6.25 之后）。

## 一、现有闸门

| # | 闸门 | 怎么跑 | 规模 | 挡住什么 |
|---|---|---|---|---|
| 1 | **单元/集成测试** | `python -m unittest discover -s tests -t .` | **480 项** | 逻辑回归：后端适配、账号管理、引导/设置/更新接口、更新器（含 sha256 与回滚）、缓存目录迁移、兼容层路径映射… |
| 2 | **面板静态自检** | `python tools/check_panel_static.py [-v]` | **50 条** | 界面接线类回归：三按钮 DOM+`data-act`+处理器、拖动区与文字可选中的互斥规则、双击最大化前后端、能力探测守卫（Linux 端 no-op）、**空 `src` 破图防线**、toast 层级高于弹窗、版本四处一致、共用文件齐备 |
| 3 | **双端一致性** | `cd <Linux 仓> && python -m unittest tests.test_dual_end_assets` | 6 项共用资产 | 两端共用文件**字节不一致**；以及"外壳耦合了某端 API / 具体插件名" |
| 4 | **真实浏览器交互验证** | `python tools/verify_panel_ui.py`（需 playwright + GUI） | 交互级 | 只有它能验"点下去真的对"：浮层开关、二维码渲染、日志回填、状态胶囊随运行态变化… |
| 5 | **打包链路自检** | `tests/test_packaging.py` + CI 出包 | — | `version_info`/windowed/`exe.config`/多尺寸 ico/`.spec` 语法（`.spec` 就是 Python，插错参数会 SyntaxError） |

## 二、当前缺口（已确认）

| 缺口 | 影响 | 计划 |
|---|---|---|
| **CI 不跑测试** ✗ | 任何回归都能照样发版（v0.6.25 就没有测试背书） | 在 `windows-build.yml` 的 *Install deps* 之后、*Build exe* 之前插两步（见下） |
| **Windows 基线 4 条失败** ✗ | 闸门一旦打开会直接红，等于没闸门 | 用户侧修：两条是 Linux-only 断言没跳平台；一条是环境自检（该挂开关或挪 `tools/`）；一条是 `console.log` 句柄未关导致临时目录删不掉（WinError 32） |
| `verify_panel_ui.py` 未实跑 | 交互级验证缺失 | 有 playwright 的机器补跑一次 |

### 建议插入的 CI 步骤（尚未加入）

```yaml
      - name: Static panel check          # 秒级，先跑，界面接线类问题立刻挡下
        run: python tools/check_panel_static.py

      - name: Run tests                   # 现有流程缺的就是这一步
        run: python -m unittest discover -s tests -t .
```

放在 *Install deps* 之后、*Build exe (onedir)* 之前 —— **先失败就不要浪费几分钟打包**。

## 三、各级闸门的边界（别过度信任）

- 静态自检 **不能**替代真实浏览器验证：它只看"接线是否齐备"，不看"点下去对不对"
- 单元测试里凡涉及 **`file://` + hub RPC 通道**的约定（信封拆包、固定路径）都是**我踩过坑后才补的测试**；
  新增 RPC 接口时务必同时加测试（`RpcEnvelopeTest` 就是那次事故的产物）
- 双端一致性只覆盖"共用文件清单"内的 6 项；`index.html` / `ui_pages.py` / `server.py` / `launch.py`
  **不属于**共用清单（桌面专属），改它们不需要同步 Linux，但也**不受**该项保护
- 迁移类行为（缓存目录一次性迁移）只测了"该搬/不该搬/只搬一次"，**没测真机大目录搬运耗时**

## 四、手工验证清单（每次发版前建议过一遍）

1. `python -m unittest discover -s tests -t .` → 全绿
2. `python tools/check_panel_static.py` → 50/50
3. Linux 仓 `python -m unittest discover -s tests` → 全绿（含双端一致性）
4. 真机双击 `astercore.exe`：窗口无边框可拖动、**右上角三按钮**（最小化 / 收起托盘 / 退出）、
   双击顶栏最大化、**文字能选中**（token/路径）、托盘菜单与主界面状态一致
5. 引导页：第①步用浏览器打开官方下载页 → ② 写配置 → ③ 启动取二维码；
   **一键建好并启动**能建出账号
6. 关于与更新：检查更新 → 下载并校验（sha256 一致）→ 应用并重启；失败能回滚
7. 解压包检查：`常见问题FAQ.md`、`docs\`、`_internal\components\lagrange\...`、`_internal\tools\ffmpeg\bin\ffmpeg.exe`
